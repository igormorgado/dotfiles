# Versioning guide

For projects using Semantic Versioning (`MAJOR.MINOR.PATCH`):

- Increase **MAJOR** for incompatible changes to the public API.
- Increase **MINOR** for backward-compatible new functionality.
- Increase **PATCH** for backward-compatible bug fixes.

Choose the version from the actual changes and the project's release policy. Commit subjects and this guide alone cannot establish compatibility. If the project uses a different versioning scheme, follow its documented rules instead.

Release notes should state the version and date, describe user-visible changes, and give concrete upgrade steps for incompatible changes.
